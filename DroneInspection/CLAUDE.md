# 下水道インスペクター（SEWER INSPECTOR）

大学「ソフトウェア作品コンテスト」の出展作品。**自由部門**で選考される（当初は土木部門だったが落選し、自由部門にシフトした）。
作品のコンセプトは「土木に興味のない子供に、10分程度で下水道点検の大切さを知ってもらうブラウザゲーム」。このコンセプトは変えない。

## 締切・評価

- 締切：2026年9月30日（ポスター・紹介動画）
- **評価対象はポスターと紹介動画のみ**。作品ファイルの提出はなく、評価者がゲームを遊ぶことはない
- 紹介動画は最長5分
- 評価者は学科の教員が主体。学生からの評価は、教員の評価が拮抗したときだけ参照される
- 評価観点：独創性 / 社会へのインパクト / プレゼンテーション / 実現可能性
- 会場での展示・子供によるプレイは想定しない

つまり実装は「動画とポスターの素材を作るための道具」。動画・静止画での見え方と、技術を教員に説明できることを優先する。

## 見せ方の方針

- **主役はドット絵版**。3D版は「同じゲームを別の描画方式で作った」比較用
- 動画では、子供向けのコンセプトより「プレイ画面の派手さ」「楽しそうに見えること」を重点的に見せる
- 評価者は操作しないので、画面を見ただけで「何が起きたか」が伝わる演出を優先する
- 下水道点検の大切さ（社会へのインパクト）は、ポスターと動画のナレーションで伝える

## 技術構成と制約

同じゲームを描画方式だけ変えた2つの版がある。ビルドなし、素の JavaScript。

| 版 | ファイル | 描画 |
|---|---|---|
| ドット絵版（主役） | `pixel.html` / `pixel.js` | Canvas 2D だけの自作疑似3D（Three.js 不要） |
| 3D版（比較用） | `index.html` / `script.js` | Three.js **r128**（CDN から読み込み） |

- `style.css` は両方の版で共通。ドット絵版だけの見た目は `pixel.html` の `<style>` に書く
- **3D版は比較用として凍結**。ドット絵版に入れた演出・仕様変更（デルタタイム、ランク、曲がる管など）は3D版には入れない。両版の同期も不要
- Three.js は r128 を使う。新しい版の API（import 構文、r150 以降の変更点など）は使わない
- 画像・音声の外部ファイルは使わない（「外部アセット0」をアピールしている）
  - テクスチャ・ドット絵・文字（5x7 ドットフォント）は実行時に生成、効果音と BGM は Web Audio API で合成
- ゲームパッド・キーボード・マウスのどれでも遊べる状態は保つ（ただし評価者は遊ばないので、これ以上の作り込みは不要）

## 動かし方

```
python3 -m http.server 8000
# → http://localhost:8000/index.html（3D版） / http://localhost:8000/pixel.html（ドット絵版）
```

変更後は最低限 `node --check script.js`（`pixel.js` も）で構文チェックする。
この開発機には node / python が入っていないため、その場合はローカルサーバーを立ててブラウザで読み込み、コンソールにエラーが出ないことで確認する。

## script.js の構成

| セクション | 内容 |
|---|---|
| `AudioSys` | Web Audio による効果音・プロペラ音 |
| `ANOMALY_INFO` / `CODEX_ORDER` / `TRIVIA` | 異常6種の図鑑データ、豆知識 |
| `create*Texture` | コンクリートのカラー / バンプ / ラフネスマップ生成 |
| `create*`（Leak, Sediment, Roots, Corrosion, Crack, Rebar） | 障害物・異常のメッシュ生成 |
| `hazards` / `anomalies` / `registerObject` | オブジェクト管理 |
| `manholes` | マンホール整備ポイント（回復＋豆知識） |
| `startGame` / `togglePause` / `resetGame` | 状態遷移 |
| `setPauseSel` / `decidePauseSel` / `updatePauseBtn` | ポーズメニュー（つづける / やめてタイトルへ）と画面上のポーズボタン |
| `Pad` | Gamepad API（左スティック/十字キー移動、A/R2 で中央スキャン、START でポーズ、ポーズ中は上下で選択・A で決定・B で再開） |
| `tryScan(ndcX, ndcY)` | 点検判定。マウスとゲームパッドの両方から呼ばれる |
| `updateTargetLock` | 中央に対象を捉えるとレティクルを黄色にする |
| `showClearScreen` / `renderCodex` / `householdComment` | 点検レポート、図鑑、守った世帯数 |
| `animate` | メインループ |

## pixel.js の構成（script.js と違うところ）

図鑑データ・`Pad`・ポーズメニュー・結果画面などは script.js とほぼ同じ。違うのは次の部分。

| セクション | 内容 |
|---|---|
| `setupScreen` / `cam` / `focal` | 縦180ピクセル固定の低解像度画面。`cam` はドローンの位置（「まっすぐな管」の座標系）。`focal` はスピードに応じて変わる焦点距離 |
| `Music` / `AudioSys.play*`（追加分） | Web Audio で合成するチップチューン BGM（8小節ループ。増水中は `intense` でテンポアップ）、カウントダウン・サイレンなどの効果音 |
| `zoneTextures`（`createPipeTexture` / `createBrickTexture` / `createTrunkTexture`） | 区間ごとの管テクスチャ（コンクリート → レンガ → 幹線） |
| `ZONES` / `courseCenter` / `floodAmountAt` | コースの定義。100mごとの区間、管の曲がり（中心線のずれ）、増水イベント（160mで警報、170〜236mで水位が上下） |
| `updateBend` / `bendAt` | 管の曲がりの前計算。**当たり判定はまっすぐな管の座標のまま計算し、描画のときだけ曲げる**（レースゲームと同じ方式）。カーブでは遠心力で外側へ流される |
| `FONT` / `drawText` | 5x7 ドットフォント（英大文字・数字・記号のみ） |
| `createDroneFrames` / `CAM_UP` / `CAM_BACK` | ドローンのドット絵。カメラはドローンの少し上・後ろから追いかける |
| `FX` | 演出：破片、広がる輪、飛び出す数字、フラッシュ、画面のヒビ、スピード線、中央の大きな文字（`showBanner`） |
| `renderTunnel` | 1ピクセルずつ視線と管の交点を求めて描く（曲がった管は二分探索）。水面は高さを持つ水平な面。明るさは6段階＋ディザ。デカールの番号と奥行きを `idBuf` / `depthBuf` に記録 |
| `renderWorld` | 障害物・光の柱・破片・ドローンを奥から順に描く。水面より下は切り取る |
| `renderOverlay` | 画面に重ねる演出（スピード線、コンボ、警告灯、体力低下の赤いふち、フラッシュなど） |
| `renderCity` | ゴール後、マンホールから地上へ飛び出したときの晴れた街の場面 |
| `pickTarget` / `tryScan` | 点検判定。壁の異常は `idBuf`、障害物は描いたスプライトの範囲で調べる。点検した障害物は砕けて消える |
| `animate` | メインループ。経過秒（dt）で動く。カウントダウン → プレイ → ゴール演出 / 墜落演出。当たった瞬間は `hitStop` で一瞬止める |

## 文章・表記のルール

- コードのコメントは日本語
- 画面の文言は小学生が読める言葉で。難しい用語にはふりがなを添える（例：腐食（ふしょく））。評価者は教員だが、作品のコンセプト（子供向け）に合わせる
- 土木の事実は正確に書く。根拠のない数値には「ゲーム内の目安」と明記する（例：守った世帯数）。ポスター・動画に載せる事実も同じ

## 既知の課題

ドット絵版で解決済み（3D版は凍結のため未対応のまま）：

- デルタタイム対応（経過秒で動く）
- ランクの分母：発見率は「見つけた壁の異常 / 壁の異常の総数」。障害物は分母に入れない。しきい値は S 70% / A 50% / B 30%（ゲーム内の目安。実際に遊んで調整する）
- 点検と回避の矛盾：点検した障害物は砕けて消える。見逃しに数えるのは壁の異常だけ

残っている課題：

1. **描画の重さ**：演出を足した結果、開発機で管の描画が1フレーム 7〜8.5ms（以前は約3ms）。60fps には収まるが、録画ソフトと同時に動かすと落ちる可能性がある
2. **リスタートしても配置が同じ**：オブジェクトの生成がロード時の1回だけ。撮影のときは、配置を固定できたほうが撮り直しやすい面もある
3. **難易度の調整**：遠心力の強さ（`animate` 内の係数 0.08）や増水の水位は、実際に遊んで調整が必要
4. **CDN 依存**（3D版のみ）：Three.js と Google Fonts を CDN から読んでいる。撮影時にネットにつながっていれば問題ない
